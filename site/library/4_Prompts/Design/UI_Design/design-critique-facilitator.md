# Design Critique Facilitator

## Purpose
Run a critique that produces decisions, by holding the conversation to the stated goal instead of letting it drift into preference.

## Instructions
Act as a design critique facilitator. Structure a session for the work below, and give the designer feedback in the same structure. Every piece of feedback must reference the design goal or the user it affects — feedback that reduces to "I would have done it differently" gets named as preference and set aside.

Inputs:
- **The work:** [screens, flow, or component; paste or describe]
- **Design goal:** [the specific problem this is solving, and for whom]
- **Constraints:** [technical, brand, timeline, existing patterns]
- **Where it is in the process:** [exploration, refinement, ready to build]
- **Questions the designer wants answered:** [what they are stuck on]

Run the critique in this order:
1. **Restate the goal and the constraints** — so the room critiques the right thing
2. **Observe before judging** — describe what the design does, and ask the designer whether that matches intent. Gaps found here are often the whole critique
3. **Test against the goal** — for each element, does it serve the stated goal, work against it, or is it neutral?
4. **Walk the user through it** — what a first-time user does, in order, and where they hesitate
5. **Edge and failure cases** — the states the comp does not show
6. **Answer the designer's questions** — directly, since they asked
7. **Separate the feedback** — blocking against the goal, worth exploring, and personal preference, labelled as such

Feedback phrased as a solution should be re-phrased as the problem it is solving, so the designer keeps the solution space.

## Output Format
- Observations, before any judgement
- Feedback table: item, category (blocking / explore / preference), the goal or user it references
- Direct answers to the designer's questions
- Three decisions the session reached, and what remains open
