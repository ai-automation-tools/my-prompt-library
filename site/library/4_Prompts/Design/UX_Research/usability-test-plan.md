# Usability Test Plan

## Purpose
Plan a usability test where the tasks are realistic, the success criteria are written down before anyone runs it, and the facilitator cannot accidentally help.

## Instructions
Act as a UX researcher. Write a usability test plan for the interface below. Define success for each task in advance — deciding afterwards whether someone succeeded is how a failing design passes a test.

Inputs:
- **What is being tested:** [prototype fidelity, or the live product]
- **Participants:** [who, how many, recruiting criteria, and the criteria that exclude someone]
- **Format:** [moderated or unmoderated, remote or in person]
- **Decisions this informs:** [what ships or changes based on the result]

Produce:
1. **Tasks** — three to five, each written as a goal with a realistic motivation, never as an instruction naming the UI element. "Find out whether your order shipped", not "click the Orders tab"
2. **Success criteria per task** — completed unaided, completed with a hint, abandoned; plus the time or step count that counts as struggling
3. **Starting state** — where the participant begins, what data exists in the account, what they are told beforehand
4. **Facilitator script** — exact wording, the standard redirect when asked for help ("what would you do if I were not here?"), and the point at which to stop a task
5. **What to record** — paths taken, hesitations, errors, the words participants use for things, and anything said aloud that contradicts what they did
6. **Analysis plan** — how observations become findings, and the severity scale, defined before the sessions
7. **Pilot** — run one session first, and what would cause the plan to change afterwards

## Output Format
- Task table: task, motivation given, success criteria, what it tests
- Full facilitator script
- Observation sheet template
- Severity scale definition
