ai-automation-tools · open source · prompt templates

Prompt templates you can find, copy and keep.

My Prompt Library is a full-stack prompt-template manager. Browse a curated public library of prompts, agents, guides, skills and system prompts, then sign up to save, edit and organise your own in My Library.

Open the library Source on GitHub Run it locally

The hosted app is free to browse. An account is only needed for My Library.

Features

What it does

Two libraries behind one search box: a public one versioned in Git, and a personal one stored in Postgres.

Public Library

Browse curated templates organised by section, category and subcategory, rendered from markdown. Copy any one into your own library.

library/ · Git-versioned

My Library

Sign up and create, edit, tag and delete your own prompts. Passwords are bcrypt-hashed and sessions last 30 days.

PostgreSQL · Neon

Search and ⌘K

Fuzzy search with Fuse.js, ranked so titles that start with or contain your query come first. A ⌘K palette reaches every prompt, section and theme.

Fuse.js

Skill Packs

Curated bundles of related skills for a domain or workflow. Add a pack to My Library, or download the whole thing as a ZIP for offline use.

ZIP download

16 themes

The default is the org palette shared with ai-automation-tools.dev. Your pick is remembered per browser, and each section carries its own accent.

responsive

Provenance you can check

Vendored skills and agents record their upstream source in frontmatter, and a weekly workflow reports any that have drifted behind it. It never edits content.

upstream-drift.yml

How it works

One Express app, two kinds of storage

Public content lives in files under Git; user data lives in Postgres. The same Express app serves both, in development and on Vercel.

1

Markdown in Git

The Public Library is markdown files in library/, so every change is a reviewed commit.

2

Index at build time

npm run build:index walks the library into api/prompt-index.json. CI fails a PR if the committed index is stale.

3

One API

api/index.ts runs as a Vercel serverless function in production and is imported by server.ts in development. There is no second copy.

4

React front end

React 19, TypeScript, Vite 6 and Tailwind v4. Listings load metadata only; a prompt's body is fetched when you open it.

Quick start

Run it locally

From the README. You need Node and a Neon PostgreSQL connection string; without DATABASE_URL the public library still loads, but sign-in and My Library don't.

local development 
# Clone the repository
$ git clone https://github.com/ai-automation-tools/my-prompt-library.git
$ cd my-prompt-library/site

# Install dependencies
$ npm install

# Set up environment variables
$ cp .env.example .env
# Add your DATABASE_URL (Neon PostgreSQL connection string)

# Start development server
$ npm run dev

# Visit http://localhost:3010
checks (CI runs all of these) 
$ npm run lint          # tsc --noEmit
$ npm run test:routes   # the API route table is intact
$ npm run build:index   # rebuild api/prompt-index.json after editing library/
